# Project Context Capability

## Purpose

Load durable repository facts before work starts so changes use the right paths, verification, and approval boundaries.

## Trigger When

- the task touches an unfamiliar area
- multiple tool surfaces may be involved
- ownership or verification path is unclear

## Workflow

1. read `docs/ai/project-context.md`
2. identify active paths and affected surfaces
3. surface risk, approval, and verification constraints
4. hand off to the next capability with concrete repo facts

## Output Contract

- affected paths
- active surfaces
- likely verification path
- approval notes if relevant
