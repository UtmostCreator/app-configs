## TL;DR for the reviewer

Personal `app-configs` repo migrated from a flat `configs/` + ad-hoc
deploy-by-hand layout to a four-tool installable stack:

- **chezmoi** owns dotfiles (file rendering only — no orchestration)
- **mise** owns runtimes + repo tasks
- **Nix + Home Manager** owns CLI packages (`home.packages` only)
- **nix-darwin** owns macOS system defaults + Homebrew cask bridge
- **Lefthook** owns git hooks
- `scripts/bootstrap.sh` orchestrates the cold start; `mise run sync`
  previews, `mise run sync:apply` applies (snapshot first)

All four supported hosts have a profile: `macos`, `linux-desktop`,
`linux-cli`, `wsl`. Windows native is explicitly **out of scope**.

## What to look at first (highest-friction review surfaces)

In order of "if anything goes wrong, it goes wrong here":

1. **`home/.chezmoiignore`** — pattern selectors use **target** paths
   (`.config/karabiner`, not `dot_config/karabiner`). This was a bug
   we already hit and fixed in the last commit. If you change a gate,
   re-run the four-profile chezmoi-diff check in
   [`repo-docs/migration-audit-2026-05-24.md`](repo-docs/migration-audit-2026-05-24.md)
   before merging.

2. **Ghostty deploys to two different paths per OS.** Single source of
   truth body at `home/.chezmoitemplates/ghostty/config.body.tmpl`,
   two wrappers:
   - `home/dot_config/ghostty/config.tmpl` → `~/.config/ghostty/config`
     (Linux/WSL desktop)
   - `home/Library/Application Support/com.mitchellh.ghostty/config.tmpl`
     → `~/Library/Application Support/com.mitchellh.ghostty/config`
     (macOS only — overrides the XDG path which Ghostty also reads)
   `.chezmoiignore` makes each host deploy to **exactly one** path.

3. **`home/personal.yaml.example` lives OUTSIDE `.chezmoidata/`.**
   chezmoi autoloads every `*.yaml|*.toml|*.json` inside
   `.chezmoidata/` and fails on `.example` suffix. If you move it
   back, the very first `chezmoi diff` on a fresh clone fails with
   `.example: unknown format`. `scripts/validate-config.sh` has an
   explicit anti-regression rule that errors if the file reappears
   in `.chezmoidata/`.

4. **`scripts/bootstrap.sh` defaults to `--dry-run`.** Reviewer test
   from any platform: `bash scripts/bootstrap.sh` must not mutate
   anything. The literal `--yes` is the only switch that mutates.
   `CI=true` plus no tty also unblocks non-interactive apply.

5. **`mise run sync` is a preview alias.** Only `mise run sync:apply`
   mutates, and it snapshots `~` to
   `~/.local/state/dotfiles-snapshots/<UTC>/` before any `chezmoi
   apply`. This is intentional — there is no `sync = apply` shortcut.

6. **`nix/modules/home/*` may NOT contain `mise`, `chezmoi`,
   `home-manager`, `lefthook`, or `direnv`.** The first four are
   bootstrap-installed via `nix profile`. `direnv` was DROPPED in
   Phase 3 because mise per-project env activation replaces it.
   `scripts/validate-config.sh` enforces both rules.

7. **The two-commit reclassification.** Commits `0e614dc` (dotfiles
   doctor/policy) and `775d020` (AI infra installer/validators) on
   `main` are pre-merged; the migration branch only adds new commits
   on top. Comparing branch vs main should show **no AI-infra churn**
   (anything under `.opencode/**`, `docs/ai/**`, `tools/ai/**`,
   `packages/ai-universal-rules/**`, `scripts/ai/**`).

## Friction points I'd flag in review

- **Nothing under `nix/modules/home/*` was ever evaluated by Nix on
  the test host.** It's structurally valid but `nix flake check`
  needs a Nix-installed reviewer. The two highest-risk attributes I'd
  spot-check: `mariadb` (kept because nixpkgs `mysql-client` is
  often keg-only) and `tealdeer` (the `tldr` family has historically
  shipped under both `tlrc` and `tealdeer`; we picked `tealdeer`).
- **`scripts/test-bootstrap-docker.sh` was never executed.** It
  exists, lints clean, and the body matches the design — but no
  Docker means no live verification.
- **macOS host coverage is paper-only.** `nix/hosts/macos/`,
  `nix/modules/darwin/`, the Library/... chezmoi paths — all
  designed and committed, none executed on a Mac. Phase 8
  (system-defaults + cask bridge) is scaffolded with sane defaults
  but un-`darwin-rebuild`'d.
- **The `.opencode/**` policy widening sits uncommitted in my
  working tree** (per a previous standing instruction). That's NOT
  on this PR; the reviewer doesn't see it.
